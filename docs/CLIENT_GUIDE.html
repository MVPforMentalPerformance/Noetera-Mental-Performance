Core UX rule. On the signed‑in home screen, the primary CTA is always the 5‑day program (Start Day 1 / Continue). Results and NPP retakes are secondary.

Who this is for

This guide is for a product owner / client who needs to manage the app without touching code: understand the user journey, know what accounts you must keep, run quick health checks, and handle common requests.

Key idea You can operate the product with two dashboards: Vercel (hosting) and Supabase (users & database).

What you own (assets & accounts)

To avoid losing control of the product, ensure the client organization owns:

  • Vercel project (hosting) — who can deploy, see logs, set environment variables
  • Supabase project (users + database) — where user accounts and app data live
  • GitHub repository (source code) — where changes are stored and reviewed
  • Production domain (optional) — if using a custom domain, ensure it’s registered under the client
  • Confirm there are at least two admins on Vercel and Supabase (avoid single‑person risk).
  • Store critical credentials and recovery codes in the client’s password manager / vault.

Day‑to‑day checks (5 minutes)

Recommended weekly (or after any release):

  • Open the app on mobile and confirm it loads quickly.
  • Sign up with a test email → confirm you receive the confirmation email.
  • Sign in → see Dashboard with the program as the primary action.
  • Complete Day 1 → verify Day 2 unlocks.
  • Trigger Forgot password → verify the reset flow works end‑to‑end.

Tip Keep 1–2 dedicated test accounts. Avoid testing with real customer accounts.

Common change requests

“Can we change the program text?”

Yes — but in the current MVP, program copy is packaged with the app. That means text changes require a small developer change + deploy (usually quick).

“Can we change the audio files?”

Yes. Audio can be updated and redeployed. If you expect frequent content updates, consider a future improvement: moving copy/audio mapping into a CMS or database so updates don’t require a code release.

“Can we see results history?”

The app already stores results as history (append‑only). The MVP UI focuses on the latest result. A history screen can be added later without changing the stored data model.

Email flows (confirm & reset)

The product relies on two email-based flows:

  • Email confirmation (after sign‑up)
  • Password reset (“Forgot password”)

Common failure If users click an email link and it opens the wrong site (or shows an error), it’s almost always a misconfiguration of “Redirect URLs” in Supabase for your production domain.

What you typically do (non‑technical):

  • Keep a note of your production URL (Vercel domain or custom domain).
  • When changing domains, ask your developer to update Supabase Redirect URLs.

Data & privacy (plain English)

  • User accounts are managed by Supabase Auth.
  • App data is stored in Supabase Postgres and protected so users can only access their own records.
  • Assessment results are saved as a new entry each time (history is preserved).

Backups & recovery

Backup strategy depends on your Supabase plan. The source of truth is the Dashboard (Database → Backups).

  • Free — in this project’s current state, the Dashboard indicates that scheduled/project backups may not be available.
  • Pro — typically includes scheduled backups and retention (depends on plan/policy).
  • PITR — paid option for point‑in‑time recovery (requires appropriate plan/compute).

Minimum on Free

  • Assume there are no managed scheduled backups.
  • Create an “off‑site” logical export on a cadence and store it outside Supabase.
supabase db dump --db-url "<your-connection-string>" --file "backup.sql"

Important: database backups do not include Supabase Storage objects. If you start using Storage for files, you need a separate backup strategy.

When to contact a developer

Contact your developer/vendor when any of the following happens:

  • Users cannot sign up or do not receive confirmation emails.
  • Password reset emails fail or link opens the wrong domain.
  • The app is down, extremely slow, or shows unexpected errors.
  • You need changes to program copy/audio, scoring, or the user flow.

What to send When reporting an issue, send: your production URL, the exact steps to reproduce, and the time it happened. If possible, include a screenshot of the error.
